# 定价管理列表化改造设计规格

> **日期**：2026-06-15
> **范围**：`apps/web/src/features/pricing/` 前端交互重构
> **目标**：把单一分类和马德里定价页改成“表格为中心”的列表交互，国家筛选放到表格左上角，默认不筛选国家，新增与修改语义分离，并继续沿用现有 drawer/sheet。

## 1. 背景与目标

当前定价管理页有两个明显问题：

1. 页面右上角的国家选择器绑定全页上下文，导致“筛选”语义和“表格局部操作”耦合过紧。
2. 单一分类和马德里定价都把主要修改入口放在区块右上角按钮里，列表本身缺少稳定的行内操作语义。

本次改造的目标不是重做定价系统，而是在**不改后端接口和存储语义**的前提下，把页面调整为更稳定的运营列表交互：

1. 国家筛选下沉到表格头部，成为局部列表控制项。
2. 默认进入页面时不筛选国家，直接展示全部生效定价。
3. `新增` 只负责创建当前不存在生效记录的国家定价。
4. `修改` 只负责更新当前表格行，对应入口统一落在表格最后一列 `操作`。
5. 马德里基础费与国家费拆开处理，避免把全局数据硬塞进国家筛选模型。

## 2. 已确认决策

以下决策已在设计对齐中确认，后续 planning 和 implementation 必须以此为准：

1. 页面继续保留两个 tab：`单一分类`、`马德里`。
2. 路由继续使用一个共享的 `country_id` 搜索参数；缺省表示“全部国家/地区”。
3. 单一分类和马德里国家费默认都展示**全部生效记录**，不增加分页、搜索或列显隐。
4. 马德里拆成两个区块：
   - `马德里基础费` 小表
   - `马德里国家费` 表格
5. 基础费不受国家筛选影响。
6. 新增页继续沿用现有 drawer/sheet，不改成独立路由页。
7. 新增和筛选绑定：
   - 筛选为“全部国家/地区”时，可从所有“当前没有生效定价”的国家里新增。
   - 筛选为具体国家时，新增只服务于该国家。
8. 如果当前筛选国家已有生效定价，则 `新增` 按钮禁用，不隐藏。
9. 编辑模式下国家不可修改，只读展示；只有新增模式允许选择国家。
10. 单一分类、马德里国家费都遵守“新增只新建、修改只更新当前行”的语义分离。
11. reviewer 不显示新增按钮，也不显示 `操作` 列；admin 才能看到完整操作入口。

## 3. 范围与非目标

### 3.1 本次范围

1. 重组 `Pricing` 页面布局和表格交互。
2. 为单一分类和马德里国家费增加“默认全量列表 + 可按国家筛选”的行为。
3. 为单一分类、马德里基础费、马德里国家费整理新增/修改入口。
4. 为单一分类和马德里 drawer 引入显式 `create` / `edit` 模式。
5. 更新与上述交互相关的前端集成测试。

### 3.2 明确不做

1. 不改后端 API 形态，不新增接口。
2. 不改数据库 schema 或 `create-or-replace` 语义。
3. 不增加搜索、分页、排序控件、列显隐或批量操作。
4. 不把 drawer 中的全部字段摊平成宽表。
5. 不重做 tab 信息架构，不改成单页上下长列表。

## 4. 页面结构

## 4.1 顶层状态

页面继续由 `Pricing` 组件承载，保持以下顶层状态：

1. 当前 tab。
2. 共享的 `country_id` 搜索参数。
3. 单一分类编辑器状态。
4. 马德里基础费编辑器状态。
5. 马德里国家费编辑器状态。

`country_id` 为 `undefined` 时表示“全部国家/地区”，不再像当前实现那样默认落到第一个国家。

## 4.2 单一分类 tab

单一分类 tab 调整为如下结构：

1. 区块标题与说明文案保留。
2. 表格头部左侧放国家筛选。
3. 表格头部右侧放 `新增单一分类定价`。
4. 下方展示单一分类表格。
5. 表格最后一列为 `操作`，仅 admin 可见，列内按钮为 `修改`。

国家筛选仅控制这张表当前展示的行集合，不再放在页面右上角。

## 4.3 马德里 tab

马德里 tab 拆成两个连续区块：

### A. 马德里基础费

1. 独立的小表，只展示基础费一行。
2. 该区块不显示国家筛选。
3. 当基础费为空时，区块右上角显示 `新增基础费`。
4. 当基础费存在时，修改入口下沉到该行最后一列 `操作 -> 修改`。

### B. 马德里国家费

1. 独立的国家费表格。
2. 表格头部左侧放国家筛选。
3. 表格头部右侧放 `新增马德里国家费`。
4. 表格最后一列为 `操作`，仅 admin 可见。

这个拆分的关键原因是基础费是全局数据，而国家费才属于 `country_id` 维度。

## 5. 数据获取与筛选语义

## 5.1 查询面保持不变

继续沿用现有查询：

1. `useSingleClassPricingList`
2. `useMadridPricingList`
3. `useCountries`

不新增接口，只调整传参方式：

1. `country_id` 缺省时，请求全量生效数据。
2. `country_id` 有值时，请求该国家对应数据。
3. 马德里基础费查询始终包含基础费行，不受筛选影响。

## 5.2 国家筛选下拉

筛选下拉展示**全部启用中的国家/地区**，而不是只展示已有定价的国家。其行为如下：

1. 默认选项为 `全部国家/地区`。
2. 选择具体国家后，表格切到该国家上下文。
3. 如果该国家当前没有生效定价，表格显示筛选态空状态。
4. admin 可以在这个筛选上下文中直接新增该国家定价。

## 5.3 筛选状态共享

两个 tab 共用一个 `country_id` 状态：

1. 在单一分类中切到某个国家，再切到马德里国家费时，仍然保留该筛选。
2. 马德里基础费区块虽然不受筛选影响，但不会重置共享筛选状态。

共享筛选的目的，是让用户能在两个注册方式之间快速对照同一国家。

## 5.4 路由 loader 预取

`/_authenticated/pricing/` 路由的 loader 需要与新页面的数据依赖保持一致：

1. 始终预取国家列表。
2. 当 `country_id` 为空时，预取：
   - 单一分类全量列表
   - 马德里全量列表（包含基础费）
3. 当 `country_id` 有值时，预取：
   - 该国家的单一分类列表
   - 该国家的马德里列表（包含基础费）
4. 不再为当前页面预取 `pricing-entries` 旧查询，避免首屏加载与真实数据源脱节。

## 6. 新增与修改语义

## 6.1 总原则

前端要把现有后端的 `create-or-replace` 行为包装成两个清晰入口：

1. `新增`：只允许面向当前没有生效记录的国家创建新记录。
2. `修改`：只允许更新当前表格行，不允许借修改迁移到别的国家。

也就是说，后端仍然是 replace，但前端必须确保交互上不会让“新增”暗中变成“修改”。

## 6.2 新增按钮状态

### 单一分类 / 马德里国家费

1. 当前筛选为“全部国家/地区”时：
   - 如果仍存在可新增国家，`新增` 按钮可点。
   - drawer 国家下拉展示所有尚无生效定价的国家。
   - 如果已经没有可新增国家，`新增` 按钮禁用，并提示当前已无可新增国家。
2. 当前筛选为具体国家且该国家没有生效定价时：
   - `新增` 按钮可点。
   - drawer 国家选择锁定为当前筛选国家。
3. 当前筛选为具体国家且该国家已有生效定价时：
   - `新增` 按钮禁用。
   - 提示文案为：`当前筛选国家已有生效定价，请使用行内修改。`

### 马德里基础费

1. 如果当前没有基础费记录，显示 `新增基础费`。
2. 一旦基础费记录存在，新增入口消失，仅保留行内 `修改`。

## 6.3 Drawer 模式

`SingleClassPricingDrawer` 和 `MadridPricingDrawer` 都需要显式支持 `mode: 'create' | 'edit'`。

### 单一分类

1. `create` 模式：
   - 显示国家下拉。
   - 可选集合由“当前无生效记录国家集合”决定。
2. `edit` 模式：
   - 不显示国家下拉。
   - 只读展示当前国家。

### 马德里国家费

1. `create` 模式：
   - 显示国家下拉。
   - 仅允许选择马德里成员国家中、当前无生效国家费记录的国家。
2. `edit` 模式：
   - 不显示国家下拉。
   - 只读展示当前国家。

### 马德里基础费

继续沿用现有基础费 drawer 分支，不涉及国家字段。

## 7. 表格列与空状态

## 7.1 单一分类表

单一分类表保持高频字段，不扩展为详情宽表：

1. `国家/地区`
2. `首类（不含税）`
3. `首类（含税 6%）`
4. `首类（含税 1%）`
5. `每次类（不含税）`
6. `受理需时`
7. `注册需时`
8. `操作`（仅 admin）

其中 `国家/地区` 单元格继续保留两行信息：

1. 第一行：国家名
2. 第二行：大洲

## 7.2 马德里国家费表

马德里国家费表使用简洁列：

1. `序号`
2. `国家/地区`
3. `官费（瑞士法郎）`
4. `我所代理费（人民币）`
5. `操作`（仅 admin）

## 7.3 马德里基础费小表

基础费小表使用下列字段：

1. `类型/序号`
2. `名称`
3. `官费（瑞士法郎）`
4. `我所代理费（人民币）`
5. `操作`（仅 admin，有数据时显示）

## 7.4 空状态

空状态分三类：

1. 默认全量列表为空：
   - 单一分类：`暂无单一分类定价`
   - 马德里国家费：`暂无马德里国家费`
2. 当前筛选国家无数据：
   - `当前筛选国家暂无生效定价`
3. 马德里基础费为空：
   - `暂无基础费`
   - 同时保留 `新增基础费`

## 8. 权限与可见性

权限逻辑继续沿用当前 `admin` / `reviewer` 区分：

1. `admin`
   - 可见新增按钮
   - 可见 `操作` 列
   - 可打开 drawer 新增或修改
2. `reviewer`
   - 只看列表数据
   - 不显示新增按钮
   - 不显示 `操作` 列

不做更细的权限切分。

## 9. 代码改动边界

本次实现预计只涉及以下前端文件：

1. `apps/web/src/features/pricing/index.tsx`
2. `apps/web/src/features/pricing/components/method-pricing-drawers.tsx`
3. `apps/web/src/routes/_authenticated/pricing/index.tsx`

不改后端 handler、service、repository，也不改 API DTO。

## 10. 测试与验证

## 10.1 前端集成测试

至少覆盖以下场景：

1. 默认进入页面时，单一分类和马德里国家费都能显示全量数据。
2. 选择已有定价国家后，单一分类新增按钮禁用，且行内有 `修改`。
3. 选择无定价国家后，单一分类新增按钮可点，打开 drawer 后国家锁定为该国家。
4. 从“全部国家/地区”新增单一分类时，国家下拉只包含当前没有生效记录的国家。
5. 单一分类编辑模式下国家为只读，不显示国家下拉。
6. 马德里基础费区块始终显示且不受筛选影响。
7. 基础费为空时显示 `新增基础费`；有基础费时改为行内 `修改`。
8. 马德里国家费默认显示全量，筛选后只显示对应国家。
9. 已有国家费时，`新增马德里国家费` 按钮禁用。
10. 马德里国家费编辑模式下国家为只读。
11. reviewer 视角下看不到新增按钮和 `操作` 列。

## 10.2 人工回归

1. 在两个 tab 之间切换时，共享筛选状态保持一致。
2. 从“全部国家/地区”切到具体国家、再切回全部时，按钮状态和空状态同步更新。
3. 新增或修改保存成功后，列表刷新正确，当前 tab 和筛选状态不丢失。
4. 空状态文案能明确区分“当前无任何数据”与“当前筛选无数据”。

## 11. 风险与约束

本次改造最大的风险不在接口，而在前端派生状态链路变复杂后出现错配，例如：

1. 按钮被正确禁用，但 drawer 默认国家仍然错误。
2. 当前筛选切换后，允许新增的国家集合没有同步更新。
3. 编辑模式虽然隐藏了下拉，但提交时仍然错误地覆盖 `country_id`。

因此实现时需要遵守两个约束：

1. 把“当前筛选 -> 当前是否已有生效记录 -> 可新增国家集合 -> drawer mode/defaults”收敛成清晰的派生状态。
2. 不要把这些规则分散进多个点击处理器里临时拼接。

## 12. 推荐实现路径

按最小改动方案推进：

1. 先重组 `index.tsx`，把列表、筛选、按钮状态和行内操作理顺。
2. 再改 `method-pricing-drawers.tsx`，补齐显式模式和国家只读逻辑。
3. 最后更新路由 loader 与集成测试，确保默认全量列表和筛选态行为稳定。

这条路径能在不扩大后端范围的前提下完成本次改造，并把主要风险压在前端局部。
